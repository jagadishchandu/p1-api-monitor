2. ServiceNow OAuth application

The monitor logs in with OAuth 2.0 client credentials only. It does not use a user name or password. ServiceNow gives a short-lived token, and the monitor refreshes it automatically.

Step 1: the service account

Ask your ServiceNow admin to create a dedicated user that the OAuth application runs as:

  • User ID, e.g. svc_p1_api_monitor
  • Web service access only ticked (the account is used only by the API)
  • Active
  • A shared mailbox or team address as the contact
  • Read access to the incident table. Usually the itil role, or a read ACL. No write or admin role

Step 2: the OAuth application

1
Admin opens System OAuth > Application Registry > New and chooses Create an OAuth API endpoint for external clients.
2
Name it (e.g. P1 API Monitor) and keep it Active.
3
Enable the client credentials option (wording varies by release). Set the user it runs as to the service account from step 1.
4
Save and copy the Client ID and Client Secret. Put them in .env as SN_CLIENT_ID and SN_CLIENT_SECRET.
If the client secret is rotated or expires, the monitor fails with HTTP 401 until .env is updated. If your release has no client credentials option, the monitor cannot run on it. Ask the admin to check the release.

3. Check the OAuth login and API access

Test the credentials before starting Docker. Replace the placeholders.

Git Bash, macOS or Linux

TOKEN=$(curl -s -X POST "https://yourinstance.service-now.com/oauth_token.do" \
  -d "grant_type=client_credentials&client_id=YOUR_CLIENT_ID&client_secret=YOUR_CLIENT_SECRET" \
  | sed -n 's/.*"access_token":"\([^"]*\)".*/\1/p')
curl "https://yourinstance.service-now.com/api/now/table/incident?sysparm_limit=3&sysparm_fields=number,state,priority" \
  -H "Authorization: Bearer $TOKEN" -H "Accept: application/json"

Windows PowerShell

$tok = (Invoke-RestMethod -Method Post -Uri "https://yourinstance.service-now.com/oauth_token.do" -Body @{grant_type="client_credentials"; client_id="YOUR_CLIENT_ID"; client_secret="YOUR_CLIENT_SECRET"}).access_token
Invoke-RestMethod -Uri "https://yourinstance.service-now.com/api/now/table/incident?sysparm_limit=3&sysparm_fields=number,state,priority" -Headers @{Authorization="Bearer $tok"; Accept="application/json"}
ResultMeaning
Result list with incidentsGood
HTTP 401Wrong Client ID or secret, OAuth application inactive, or it does not run as the service account
HTTP 403Account can get a token but cannot read incidents. Ask for a role check
HTTP 404Wrong instance name

4. Teams webhook (optional)

1
In Power Automate, create or reuse a flow that starts with When a HTTP request is received.
2
Copy the HTTP POST URL. Treat it like a password.
3
Put it in TEAMS_WEBHOOK_URLS. Separate several URLs with commas.

Without a webhook, incidents are still tracked and the SWAT board still works.

5. Email over SMTP (optional)

Ask your mail team for:

  • SMTP host, e.g. smtp.yourcompany.com
  • Port: usually 587 with STARTTLS, or 25 for an internal relay
  • Login details, if the server requires them
  • A sender address the server allows

Leave EMAIL_TO empty to turn email off.

6. Create the .env file

The image contains no secrets. Settings are read from .env when the container starts.

# Windows
copy .env.example .env
# Mac / Linux
cp .env.example .env

Minimum values:

SN_INSTANCE=acmecorp
SN_CLIENT_ID=your-oauth-client-id
SN_CLIENT_SECRET=your-oauth-client-secret
AZURE_STORAGE_CONNECTION_STRING=DefaultEndpointsProtocol=https;AccountName=...;AccountKey=...;EndpointSuffix=core.windows.net

Azure Storage

The monitor keeps incidents.json, swat_status.json and swat_details/ in one blob container of an Azure Storage account. Get the connection string from the portal: storage account > Security + networking > Access keys > Connection string.

SettingMeaning
AZURE_STORAGE_CONNECTION_STRINGRequired. Contains the account key, so keep it secret
AZURE_STORAGE_CONTAINERBlob container. Default p1-api-monitor
AZURE_STORAGE_FOLDERFolder inside the container. Default p1-api-monitor
Automatic setup: the container and folders are created on first start if they are missing. You do not need to create them by hand.
Never commit .env to git or share it. It is excluded by .gitignore and .dockerignore.

7. Build and run with Docker

From the P1-api-monitor folder:

docker compose up -d --build

Host port 8080 maps to container port 8080.

Useful commands

CommandWhat it does
docker compose logs -fLive log
docker compose up -dApply changes to .env (recreates the container)
docker compose downStop and remove the container. Data is kept
docker compose run --rm p1-api-monitor python monitor.py --check-onceOne check, then exit
docker compose run --rm p1-api-monitor python monitor.py --test-notifySend a test P1 card and email
docker build does not read .env. Settings are supplied when the container runs.

Where data is kept

ItemLocation in Azure Storage
incidents.json<AZURE_STORAGE_FOLDER>/incidents.json
swat_status.json<AZURE_STORAGE_FOLDER>/swat_status.json
swat_details/<AZURE_STORAGE_FOLDER>/swat_details/<INC number>.json

The container keeps nothing locally, so it can be rebuilt or moved without losing data. Everyone who uses the board shares the same data.

8. Open the SWAT board

  • On the host: http://localhost:8080
  • From other computers: http://<host-name-or-ip>:8080 (firewall must allow port 8080)

Set SWAT_BOARD_PUBLIC_URL to the address other people use. The Open SWAT board button on Teams cards uses it.

What the board shows

  • Filters: All, In Progress, On Hold, Resolved, each with a count
  • A state label on each card with the time it changed
  • For each team (Infra Ops, Container Ops, Network Ops): Required or Not required, and who joined
  • A details and notes page per incident, with the intake form and Excel export
The board has no login. Users type their name before saving changes. Limit access to the network.

9. Test it

1
Send a test P1 card and email: docker compose run --rm p1-api-monitor python monitor.py --test-notify
2
Run one live check: docker compose run --rm p1-api-monitor python monitor.py --check-once
3
Confirm the board responds: curl http://localhost:8080/api/incidents

10. How it behaves

Every 15 minutes (MONITOR_INTERVAL_MINUTES) the monitor reads In Progress, On Hold and Resolved incidents from ServiceNow and compares them with incidents.json.

What happenedWhat the monitor does
New In Progress incidentNew incident alert, then stored
Priority changedPriority changed alert
In Progress moved to On HoldUpdate alert, state stored as On Hold
In Progress moved to ResolvedUpdate alert, state stored as Resolved
On Hold or Resolved back to In ProgressTreated as new and alerted again
Closed, Canceled, or no longer in these statesRemoved from incidents.json

An alert that fails on every channel is retried on the next check.

12. Troubleshooting

SymptomWhat to check
missing required environment variable.env is missing or a name is misspelled. Run docker compose config
HTTP 401 from ServiceNowWrong Client ID or secret, OAuth application inactive, or not running as the service account
Could not create the storage containerThe connection string is wrong or lacks permission. Copy it again from the portal
AuthenticationFailed from Azure StorageThe account key was rotated. Copy the connection string again
HTTP 403 from ServiceNowAccount lacks read access to the incident table
OAuth token request failedClient ID or secret wrong, or OAuth application inactive
Could not reach service-now.comNo internet or proxy access from the host, or wrong instance name

No alertsNormal when nothing changed since the last check

13. Security notes

  • .env holds the OAuth client secret, the storage connection string and webhook secrets. Keep it on the server only.
  • Use a read-only service account.
  • Prefer OAuth. The access token is kept in memory only.
  • Rotate the OAuth client secret and the storage account key on your admin's schedule, then run docker compose up -d.
  • The SWAT board has no login. Limit network access or put it behind an authenticated reverse proxy.
  • The Teams webhook URL is a secret. Anyone with it can post to the channel.
  • The container runs as a non-root user.
