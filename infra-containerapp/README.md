# P1 API Monitor on Azure Container Apps: Terraform and PowerShell

This folder creates **every Azure resource** the monitor needs, then deploys the app to them.

| Created by Terraform | Purpose |
|---|---|
| Resource group | Holds everything |
| Storage account and container (private) | `incidents.json`, `swat_status.json`, `swat_details/` |
| Container registry (Basic, admin user on) | Holds the app image |
| User-assigned managed identity | The app signs in to storage with it (no key) |
| Role: Storage Blob Data Contributor (on the storage account) | The identity can read and write the data files |
| Role: AcrPull (on the registry) | The app pulls its image with the identity |
| Log Analytics workspace | Container logs (30 days) |
| Container Apps environment | Runs the app |
| Container App `p1-api-monitor` | The monitor and the SWAT board, 1 replica, always on, external HTTPS ingress |

`Deploy-ContainerApp.ps1` runs the whole deployment in order: it creates the registry, asks for its user name and password, builds and pushes the image, then creates the rest.

---

## 1. Before you start

1. **Azure subscription** where you can create resources, and **Owner** (or Contributor plus User Access Administrator) on the resource group, so the role assignments can be created.
2. **Tools on this PC:**
   - Terraform 1.6 or newer (`winget install Hashicorp.Terraform`)
   - Docker Desktop, running
   - Azure PowerShell: `Install-Module Az -Scope CurrentUser`
   - Optional: Azure CLI (`az`), used only for the registry password instructions below
3. **Your settings in `..\.env`.** Copy `..\.env.example` to `..\.env` and fill in at least:
   - `SN_INSTANCE`, `SN_CLIENT_ID`, `SN_CLIENT_SECRET` (ServiceNow, required)
   - Optional alerts: `TEAMS_WEBHOOK_URLS`, `EMAIL_TO`, `SMTP_*`
   - `AZURE_STORAGE_ACCOUNT_URL` and `AZURE_STORAGE_CONNECTION_STRING` are **not used** by this deployment. Terraform creates the storage account and the app finds it itself. You can leave them as they are.

The script reads `.env` and gives the values to Terraform in memory. Nothing is printed, and secrets are not written to a file (the Terraform state still stores them, see section 6).

---

## 2. Deploy

Open PowerShell in this folder (`P1-api-monitor\infra-containerapp`) and run:

```powershell
.\Deploy-ContainerApp.ps1 -NameSuffix jc01
```

Pick a `-NameSuffix` of 3 to 12 lowercase letters or digits. Names of the registry and storage account are built from it, and they must be unique in Azure. Keep the same suffix for later runs.

What happens:

1. Signs in to Azure with a device code (open the link it shows and enter the code).
2. Reads `..\.env`.
3. `terraform init`, then **step 1**: creates the resource group, the registry and the identity.
4. **Stops at the registry and shows where to find the user name and password** (section 3). It asks for them.
5. Logs in to the registry, builds the image from the project folder, and pushes it.
6. **Step 2**: `terraform apply` creates the storage, roles, logs, environment and the container app, using that image.
7. Checks the SWAT board address and prints it.

Terraform shows the plan and asks you to type `yes` before each step. Add `-AutoApprove` to skip the questions.

---

## 3. Where to get the registry user name and password

The registry is created with its **admin user** turned on. The admin user name is the registry name itself, and the password is generated by Azure.

**In the Azure portal:**

1. Go to <https://portal.azure.com>, search for **Container registries**, and open the registry the script printed (`acrp1apimon<your suffix>`).
2. In the left menu, under **Settings**, click **Access keys**.
3. Under **Admin user**, the **Username** box shows the user name. It is the registry name.
4. Click the copy icon next to **password** (or **password2**). That is the password.

**With Azure CLI** (copy the output; do not paste it into chat or email):

```powershell
az acr credential show --name acrp1apimonjc01 --query username -o tsv
az acr credential show --name acrp1apimonjc01 --query "passwords[0].value" -o tsv
```

Replace `acrp1apimonjc01` with your registry name.

**Passing them as parameters next time**, so the script does not ask:

```powershell
$registrySecret = Read-Host "Registry password" -AsSecureString
.\Deploy-ContainerApp.ps1 -NameSuffix jc01 -RegistryUsername acrp1apimonjc01 -RegistryPassword $registrySecret -AutoApprove
```

The password is never stored in a file. Use a password you can rotate: in the portal, click **Regenerate** next to `password` and run the script again with the new one.

## 4. Check the app

- The script prints the SWAT board address at the end, for example `https://p1-api-monitor.<region>.azurecontainerapps.io`.
- Logs: `az containerapp logs show -n p1-api-monitor -g rg-p1-api-monitor --follow --type console`
- Storage: in the portal, open the storage account, then the container `p1-api-monitor`. The folder `p1-api-monitor` holds the data files once the monitor has run.

Teams cards use the SWAT board address. To use another address, set `SWAT_BOARD_PUBLIC_URL` in `.env` and run the script again.

---

## 5. Change the settings later

Edit `..\.env` (or `terraform.tfvars` for non-secret values), then run the script again with the same `-NameSuffix`. Every run builds and pushes a new image tag (the timestamp), and Terraform moves the container app to the new revision. The registry password is asked for again unless you pass `-RegistryPassword`.

---

## 6. Security notes

- **Secrets in the Terraform state.** The container app stores the ServiceNow secret, SMTP password and Teams webhook as Container Apps secrets, so `terraform.tfstate` contains them. The state is git-ignored. Keep it private, or store it in a private backend: uncomment the `backend "azurerm"` block in `versions.tf`.
- **No storage key.** The app uses its managed identity. The storage account has public blob access off and TLS 1.2 minimum.
- **Registry admin user.** It is on so the script can push. You can turn it off after the first deploy: portal → the registry → Access keys → Admin user off. The app then keeps pulling with its identity. Turn it on again before the next push.
- **Clean up everything:** `terraform destroy` (or delete the resource group `rg-p1-api-monitor`). This deletes the stored incidents and SWAT data.

## 7. Files

| File | What it is |
|---|---|
| `Deploy-ContainerApp.ps1` | Deploys: Terraform step 1, registry credentials, image build and push, Terraform step 2 |
| `versions.tf` | Terraform and provider versions, optional remote state backend |
| `variables.tf` | Every setting, with a description |
| `main.tf` | Every resource |
| `outputs.tf` | Values printed after deployment (registry address, app address, identity) |
| `terraform.tfvars.example` | Example of non-secret values. Copy to `terraform.tfvars` if you prefer a file |
